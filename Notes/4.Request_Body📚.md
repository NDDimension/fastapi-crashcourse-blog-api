## 🧾 Request Body in FastAPI

### 📌 What is a Request Body?

A **request body** contains the **data sent by the client** to create or update resources — typically in **JSON format**.

- **Used in:** `POST`, `PUT`, `PATCH` requests.
    
- **Different from:**
    
    - **Path Parameters:** Identify specific resources  
        → `/blogs/{id}`
        
    - **Query Parameters:** Filter/sort/paginate collections  
        → `/blogs?limit=10`

## 🧩 Declaring Request Bodies with Pydantic

### ✅ Use a Pydantic Model

1. Create a model by inheriting from `BaseModel`.
    
2. Use it as a function parameter → FastAPI will:
    
    - Parse the request body.
        
    - Validate data.
        
    - Auto-generate OpenAPI docs (visible at `/docs`).
        

```python
from pydantic import BaseModel

class Blog(BaseModel):
    title: str
    body: str
    published: bool = True

@app.post("/blogs")
def create_blog(blog: Blog):
    return blog
```

## ✅ Pydantic v2 Tips & Validation

### 🔠 Types Supported

- Built-in: `str`, `int`, `float`, `bool`, `list`, `dict`
    
- Extended: `datetime`, `UUID`, `Annotated`, nested models, `Union[...]`
    

### 🛑 Validation Errors

- Invalid data → `422 Unprocessable Entity`  
    Includes detailed list of validation errors.
    

### 🆚 Optional vs Required

- `Optional[T]` means the value may be `None`, but it’s still **required** unless a default is provided.
    

```python
# Required but nullable
published: bool | None

# Truly optional
published: bool | None = None
```

### 🎛 Field Constraints

Use `Field(...)` for validation and documentation:

```python
from pydantic import Field
from typing import Annotated

title: Annotated[str, Field(min_length=3, max_length=100)]
```

Also supports:

- `max_length`, `gt`, `ge`, `regex`, `description`, `examples`, etc.
    

### 🔧 Pydantic v2 Changes

- `model_dump()` → instead of `.dict()`
    
- `model_dump_json()` → instead of `.json()`
    
- `@field_validator` → replaces `@validator`
    
- Config: use `model_config` instead of `class Config`

## 📦 Multiple Body Parameters

You can define multiple body parameters in a route:

```python
def create(blog: Blog, author: Author):
    ...
```

To **embed** a single model under its name:

```python
from fastapi import Body

def create(blog: Blog = Body(embed=True)):
    ...
```

> Expects:  
> `{ "blog": { ... } }` instead of just `{ ... }`

---

## 🧠 Mixing Path, Query, and Body

FastAPI allows combining all parameter types in one endpoint:

```python
from fastapi import Query

def update_blog(id: int, blog: Blog, publish: bool = Query(False)):
    ...
```

- **Path:** Identifies the resource
    
- **Body:** Contains new data
    
- **Query:** Modifies behavior (e.g., `publish=True`)

## 🧭 Content-Type and Formats

- Default: `application/json`
    
- Clients must send correct `Content-Type` header.
    

### Special Cases:

- **Forms:** Use `Form(...)`  
    Requires `python-multipart`
    
- **Files:** Use `UploadFile` / `File(...)`

## 📤 Responses

### 🔁 Best Practices

- Use `status_code=201` for successful `POST`/create actions.
    
- Use `response_model=...` to shape and filter output.
    

```python
class BlogOut(BaseModel):
    title: str
    body: str

@app.post("/blog", response_model=BlogOut, status_code=201)
def create_blog(blog: Blog):
    return blog
```

✅ Prevents leaking sensitive/internal fields (e.g., password hashes)  
✅ Ensures consistent and documented responses

## ⚠️ Common Gotchas

| Problem                      | Explanation                                              |
| ---------------------------- | -------------------------------------------------------- |
| ❗ `Optional` without default | Still required, but allows `null`                        |
| 🤯 Boolean coercion          | Loose by default — use `StrictBool` or validate manually |
| 🔁 Sets in JSON              | Not supported — prefer `list`                            |
| 🏗 Large/nested payloads     | Use `Field(...)` constraints to manage size and shape    |

## 🧪 Quick Practice

- ✅ Add `status_code=201` to `POST /blog`
    
- ✅ Use **separate models**:
    
    - `BlogCreate`: Input
        
    - `BlogRead`: Output
        
    - `BlogUpdate`: Partial update
        
- ✅ Add `Field(...)` constraints:
    
    - `title`: `min_length=3`
        
    - `body`: `max_length=500`
        
- ✅ Accept list body:
    
    ```python
    @app.post("/tags")
    def add_tags(tags: list[str]):
        return tags
    ```
    
- ✅ Nest a model (e.g., `Author` inside `Blog`)
    

```python
class Author(BaseModel):
    name: str
    email: str

class Blog(BaseModel):
    title: str
    body: str
    author: Author
```
